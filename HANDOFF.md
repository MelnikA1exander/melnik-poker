## 3. Архитектура

```
Браузер (index.html, GitHub Pages)
   │  fetch POST, Content-Type: text/plain, тело JSON {action, ...}
   ▼
Google Apps Script doPost / doGet  (выполняется от имени владельца, доступ «Все»)
   │  SpreadsheetApp.getActiveSpreadsheet()
   ▼
Google Таблица: листы создаются сами
   Сессии | Раздачи профиля | Префлоп | Последние 300 | Аккаунты | Входы
```

- Ответы читаются обычным `fetch` (`api()` в `index.html`). Сохранение сессий/решений идёт через `fetch(..., {mode:'no-cors'})` с 3 повторами (функция `persist`), т. е. ответ не читается.
- `text/plain` выбран специально: так нет CORS-preflight, который Apps Script не умеет.
- Вход хранится в `localStorage` (ключ `pc-auth` = `{token, login}`), тема — `mp-theme`, локальная статистика — `pt-preflop-v2`.
- Если `ENDPOINT` пустой — приложение работает офлайн, результаты только в браузере.

### 3.1 API Apps Script (`apps-script.gs`)

| action | вход | выход |
|---|---|---|
| `register` | `{login, password}` (логин 2–25 символов, пароль 4–25, других требований нет) | `{ok, token, login}` / `{ok:false, error:'login_format'|'password_format'|'login_taken'}` |
| `login` | `{login, password}` | `{ok, token, login}` / `bad_credentials`; 8 неудач за 15 мин → блок (CacheService) |
| `me` | `{token}` | `{ok, login}` / `{ok:false, error:'auth'}` |
| `logout` | `{token}` | `{ok}` |
| `stats` | `{token}` | `{ok, login, all, last300, last100}`, в каждом `{sessions, hands, gto, acc, vpip, pfr, type, …}` |
| `history` | `{token}` | `{ok, dec}` — последние ≤300 префлоп-решений игрока (GTO тест + «Префлоп») из листа «Последние 300» |
| `preflop` | `{token, id, started, dec}` | `{ok}` — личный журнал режима «Префлоп» (лист «Префлоп»), наружу не отдаётся, в stats не входит |
| без action | `{id, name, started, updated, summary, dec, token?}` | сохранить завершённый GTO тест; тот же `id` → обновить строку |

`doGet` создаёт все листы и возвращает `{"ok":true,"sheet":"Сессии"}` — это проверка, что деплой жив.

Ручные функции (запуск из редактора Apps Script): `rebuildHands` (пересобрать лист «Раздачи профиля» из «Сессий»), `compactStorage` (ужать сетку, почистить старые токены), `cellsUsed` (посчитать ячейки; лимит Таблицы 10 млн, один тест ≈180 ячеек).

Хранение: «Сессии» — источник истины (одна строка на тест, решения в JSON-колонке). «Раздачи профиля» — указатель «время / аккаунт/тест/№ / раздача текстом». «Последние 300» — скользящее окно на аккаунт.

## 4. Как восстановить инфраструктуру с нуля

### 4.1 Хостинг
1. Создать/использовать репозиторий на GitHub, залить содержимое `repo/` (или `git push` из клона `repo.bundle`).
2. Settings → Pages → Source: **Deploy from a branch**, `main`, `/ (root)`. Файл `.nojekyll` уже есть.
3. Сайт появится на `https://<user>.github.io/<repo>/`. Пути в `index.html` относительные (`favicon.svg`, `apple-touch-icon.png`), так что работает из любой подпапки.

### 4.2 База (Google Таблица + Apps Script)
Подробно в `repo/apps-script/apps-script-setup.md`. Кратко:
1. Создать Google Таблицу → Расширения → Apps Script → вставить `apps-script.gs` → Сохранить.
2. Развернуть → Новое развертывание → тип «Веб-приложение», «Выполнять как: Я», «Доступ: Все» (именно «Все», без входа) → Развернуть → дать разрешения («Дополнительно → Перейти»).
3. Скопировать URL `…/exec`, открыть в браузере → должно быть `{"ok":true,"sheet":"Сессии"}`.
4. Вписать URL в 3-ю строку `index.html`: `const ENDPOINT='<<APPS_SCRIPT_EXEC_URL>>';`, закоммитить, запушить.

Важно: новое развертывание = новый URL, все старые аккаунты останутся в старой таблице. Для переноса данных скопируйте листы «Аккаунты», «Входы», «Сессии», «Раздачи профиля», «Префлоп», «Последние 300» в новую таблицу.

### 4.3 Обновление скрипта без смены URL
Apps Script → заменить код → Сохранить → Развернуть → **Управление развертываниями** → карандаш → Версия: **Новая версия** → Развернуть. («Новое развертывание» создаст другой URL — так не делать.)
Из облачного окружения Claude доступ к script.google.com был закрыт, поэтому этот шаг всегда делал владелец руками.

### 4.4 Проверка после восстановления
- Открыть сайт → зарегистрироваться (логин с «тест» в имени — такие владелец считает своими тестами) → сыграть GTO тест 50 раздач → в таблице появляется строка в «Сессии» и 50+ строк в «Раздачи профиля».
- Открыть «Профиль» (кнопка в шапке) → карточки и график стиля.

## 5. Приложение `index.html`: устройство

Один файл, ~2600 строк, весь JS в одном `<script>` (с ~441 строки). Без фреймворков. Важные блоки (имена функций/констант для поиска):

**Карты и чарты**
- `RANKS`, `expand`, `chart`, `cls` — нотация рук 13×13, разбор строк диапазонов.
- `RFIF`/`chartF`/`RFI` — опены (raise first in) по числу игроков позади; `VSF`/`chartVS`/`VSOPEN` — ответы на опен (3-бет/колл); `VS3B`, `COLD3B`, `FACE4B`, `COLD4B`, `FACEJAM`, `DEEP` — дальше по дереву. Миксы хранятся с частотами (проценты показываются в ячейках).
- `ALL169`, `lineRange`, `openRange` — диапазон игрока по всей его линии (для кнопки «+»).
- `eval7`, `equity`, `equityVsRanges`, `eqVsLists` — оценка 7 карт и Монте-Карло эквити (5–12 тыс. раскладов, ±0,5–1%).

**Раздача и торговля**
- `newHand`, `setupHand`, `deal`, `shuffled`, `seeded`, `NATIVE_RANDOM` — честная раздача: в начале перемешивается колода, сразу сдаются все руки и 5 карт борда, потом ничего не пересдаётся.
- `decisionFor`, `allowedFor`, `heroDec`, `heroAct`, `botAct`, `botSize`, `apply`, `run`, `checkOver`, `finishHand`.
- `sizeBands(d)` — нормы сайзинга (см. §6.3).
- Постфлоп (режим «Полная раздача»): `strat`, `papply`, `pbot`, `advance`, `showdown`, `heroStrat`, `gradePost`, `sizeBandPost`, `postBlock`.

**Отрисовка**: `render`, `renderTable`, `renderActions`, `renderEnd`, `gridEl`, `decBlock`, `explain`/`whyText` (тексты «Почему…»), `renderStats`.

**GTO тест (бывший «Профиль»)**: `startRun`, `recPick`/`repPick`/`recKeep`/`bandKeep` (подбор раздач), `SQUOTA`, `need3b`/`need4b`, `recDecision`, `profAnalyze`, `irtScore`, `styleXY`, `zoneOf`, `xyType`, `classifyType`, `histType`, `xyPlot`, `addBlobs`, `cloudURL`, `gtoSizing`, `sizeTells`, `resSummary`, `profTips`, `tipLevel`, `TPS`, `advRanges`, `renderResults`, `goBack`/`replayPrev`.

**Вкладка «Диапазоны»**: `showRanges`, `renderRanges`, `rngCharts`, `anyMode`/`anyGrid`/`anyUpd` (Any range по PokerStove-порядку `ANY_ORD`).

**Аккаунты и профиль**: `api`, `showAuth`, `authSubmit`, `authErr`/`AFIELD` (подсветка именно ошибочного поля), `doLogout` (с подтверждением `askConfirm`), `openProfile`, `loadHist`.

**Прочее**: `HELP_HTML`/`openHelp` (кнопка «Справка»), `syncTheme` (свитч темы, самый левый в шапке), `setMode`, `indTaps` (секретное включение индивидуального режима — 3 нажатия за 1,5 с).

### 5.1 Режимы (вкладки)
1. **GTO тест** (по умолчанию, первый). 50 раздач без подсказок, соперники — GTO-боты. Счётчик «Раздача N из 50» над банком. В конце — итог: тип игрока, шкала «Верные решения» (по делениям), «Соответствие GTO», график стиля, 6 плиток статистики (сетка 3×2), советы, сайзинг, таблица раздач с разворотом (открыта одна). Можно вернуться на 1 раздачу назад и один раз переиграть её. Кнопка «Рестарт» слева, выбор стола блокируется после старта. В базу пишется **только завершённый** тест.
2. **Префлоп ∞** — бесконечная тренировка с разбором после каждой раздачи. Решения пишутся в закрытый лист «Префлоп» (только для владельца по запросу), в статистику аккаунта не идут. Блок «Статистика» показывается только здесь.
3. **Полная раздача** (бейдж beta) — до вскрытия, постфлоп по модели эквити против суженного диапазона и порогов; пограничные решения (±3 п.п. от порога) засчитываются в обе стороны с пояснением «… тоже верно».
4. **Сайзинг** — видна, но неактивна (план: тренировка быстрого счёта сайзинга от банка).
5. **Диапазоны** — отдельная оранжевая кнопка вне бара режимов. Стол 6–10 max, действие Open / Raise/Call (выбор опенера), свёрнутые строки по позициям с сеткой 13×13 и процентами миксов. Any range — ползунок 0–100% лучших рук.

Переключатель **GTO / Индивидуальный**: индивидуальный (соперники — профили друзей из документа стратегии) закрыт для всех с пометкой «скоро», открывается тройным нажатием; знает только владелец.

## 6. Ключевые правила и формулы (не менять без согласования с владельцем)

### 6.1 Чарты
- Эталон: «идеальные GTO-боты при 125 ББ, без рейка и анте» — **не** эксплойты домашней игры.
- Источники: солверные проценты Pokalab (6-max 100bb), списки GTO Gecko / Preflop Wizard, BeyondGTO, блог GTO Wizard; поправка на отсутствие рейка (шире, особенно защита BB) и 125 ББ (пары/одномастные ценнее). Ширина опена зависит от числа игроков позади (CO одинаков на любом столе). Опены без рейка: BTN 48%, CO 31,5%, HJ 24%, LJ 19%, SB 47%, UTG 9-max ≈12%. BB vs BTN: 3-бет 13% / колл 48%.
- Это модель, а не выгрузка солвера: ширины ±1–3 п.п., частоты миксов — оценка. Собственная оценка точности ≈8/10.
- Все боты и вся оценка решений во всех режимах используют одни и те же актуальные чарты.

### 6.2 «Соответствие GTO» (балл теста) — `irtScore`
Каждое решение получает сложность по близости руки к границе GTO-диапазона. Балл = взвешенная доля верных: **сложные ×2, средние ×1, лёгкие ×0,5**; верное действие с неточным размером = 0,75. Пороги текста: **≥88%** «очень близко к оптимальной», **≥70%** «крепкая база, но есть утечки», **≥55%** «заметно отличается». Самые грубые ошибки (сброс AA/KK/AKs, пуш мусором) считаются выбросом и в оценку стиля не идут; средние ошибки весят больше пограничных.

### 6.3 Сайзинг (`sizeBands`)
- Опен: норма **2,5–3 ББ** (10–12 фишек) + 1 ББ за лимпера; из SB ≈3 ББ. Боты-GTO открывают на 10.
- 3-бет: ×3–3,5 в позиции, ×4–4,5 без позиции, + опен за каждого коллера. 4-бет: ×2,2–2,8 IP / ×2,5–3,2 OOP.
- Отклонение ≤2 фишки (0,5 ББ) от нормы — не неточность. Размер **в 2 раза больше/меньше нормы и более** (в т.ч. олл-ин вместо 3-бета) — **ошибка** с пояснением.
- Совет (без ссылки на автора): против лузовых игроков после тебя опен 3 ББ + 0,5 ББ за каждого частого коллера (≈3,5 ББ), один размер на весь диапазон. Показывается только в общих выводах, не в разборе раздач.

### 6.4 Подбор раздач в GTO тесте
Квоты ситуаций `SQUOTA` (opens EP/MP/LP/SB, защита BB/SB/IP, vs3b), минимум ~6 спотов на 3-бет, 1–2 на 4-бет (ищутся прогоном раздачи по GTO на тех же картах), 5 на колл против опена. Овершут: первые руки дальше от предполагаемой границы игрока, затем сходятся к ней. Нижние ~18% рук не раздаются. Лимп правильным ответом в GTO-чартах не бывает.

### 6.5 Профиль и координаты стиля
- Тип и координаты в окне «Профиль» считаются по **последним 300** префлоп-решениям (GTO тест + Префлоп), свежие весомее (решение 150 ходов назад ≈ в 3 раза легче). Переключатель «Последние 300» (слева, по умолчанию) / «Последние 100».
- X: тайт ↔ луз (граница диапазона игрока против GTO, по ситуациям; ось откалибрована константой `XY_RX0` по боту, играющему строго по чартам). Y: пассив ↔ агрессия.
- Тип берётся из зоны на плоскости (`zoneOf`), поэтому тип и точка не противоречат. Одна зона «Нит». Тип «Непоследовательный» — когда ситуации разбегаются (сырой разброс по ситуациям с ≥15 решениями).
- Отрисовка: только **облако** (бутстрап 160 пересборок реальных решений; малые выборки ситуаций подтягиваются к центру пропорционально объёму), при высокой уверенности — жирная точка. Эллипсы владелец не хочет.
- Справа от графика — вертикальная шкала точности сайзинга 0–100% (градиент красный→зелёный).
- Меньше 50 раздач на аккаунте — размытый график с надписью «Сыграй 50+ раздач в режимах GTO тест или Префлоп». Во время загрузки — размытый график и компактная карточка с вращающейся фишкой из фавикона (интерфейс не прыгает).
- Подпись «Префлоп профиль» (постфлоп-профиль запланирован, пока нигде не добавлять).

### 6.6 Советы в итогах теста
Только по GTO (никаких домашних правил). Тон по уровню игрока (мягко / средне / база для слабых). Ошибки — по-человечески, с классами рук и кликабельными номерами раздач («Посмотреть: №15 A6o»), клик раскрывает раздачу в списке ниже. Советы — в рамке на подложке курсивом в конце каждого блока. Блок «Против кого как играть»: GTO — база, дальше подстройка под лузовых/тайтовых/агрессивных. «Почему…» в разборе ошибок — 2–3 короткие фразы с эквити, без «задротства».

### 6.7 UX-решения владельца (держать)
- Стол 8/9/10, карты лежат на месте игрока, 5 гнёзд под борд; кнопки Фолд/Чек/Колл/Рейз никогда не исчезают (только становятся неактивными), поле размера всегда под кнопками, по умолчанию минрейз; пресеты ×2/×3/×4 от последней ставки и олл-ин; клавиши F/X/C/R/Enter.
- Кнопка «Начать раздачу» поверх пустого стола; при смене вкладок стол сбрасывается.
- Действия соперников проигрываются с задержкой 0,5 с, плашка действия под стеком только у последнего сходившего; подсвечен только активный игрок.
- В конце: карты открываются только у тех, кто действовал; над картами эквити своей руки против диапазона соперника; «+» поверх карт снизу открывает диапазон линии.
- Шапка одинакова на всех вкладках (ничего не прыгает), название «Melnik Poker», «Справка» короткая и общими словами, без упоминания домашней игры и друзей.
